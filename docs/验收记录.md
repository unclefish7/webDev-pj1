## 2. 最终自动化检查

实际执行：

```sh
docker compose exec app npm run check
docker compose exec app npm run build
docker compose exec app npm test
docker compose exec app npm run test:e2e
docker compose exec app npm run verify:import
```

结果：

- 类型检查：后端 tsc、前端 vue-tsc 均通过。
- 构建：后端编译和前端 Vite 构建均通过。UI 库约 917 KB（压缩前），仍有超过 500 KB 的体积提示；这不是构建失败，后续可按需注册控件。
- 单元/接口/通信：**9 项通过，0 失败**。覆盖的具体断言见 tests/unit.test.mjs、integration.test.mjs 和 smoke.test.mjs。
- Chromium 浏览器：**4 项通过，0 失败**，最终运行约 15.6 秒。覆盖桌面/手机、空结果、模拟失败与重试、组件 CRUD、CVE 操作和日志快照。
- 原始字段核对：**1000 条漏洞、398 条组件全部原始字段逐值一致**，证明自动化测试与录屏没有改写或删除教师记录。

## 3. 持久化验证

```sh
docker compose exec app node tests/persistence-fixture.mjs prepare
docker compose up -d --force-recreate --wait --wait-timeout 300
docker compose exec app node tests/persistence-fixture.mjs verify
```

实际结果：组件与 CVE 的修改内容和 revision 仍存在；各自已经删除的测试记录仍返回 404；操作日志保留；启动时重新运行初始化没有恢复已删除记录。验证成功后清理独立测试夹具。

## 4. 全新环境复现

创建 webdev-pj1-clean 独立 Compose 项目，使用单独的 MySQL/node_modules 卷和 53307、53000、55173 端口，挂载同一份源码和开发镜像。首次启动无需手工建表：启动脚本自动安装依赖、建表、导入并启动前后端。

实际初始状态为：1000 条漏洞、398 条组件、0 条操作日志。通过前端端口访问 /api/stats 得到 HTTP 200；全字段核对通过。验收结束后只清理该独立项目的容器及临时测试卷，主项目保留。
