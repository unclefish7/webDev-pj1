# 《现代 Web 开发》课程项目实验·Part-1

## 一、基本信息

| 项目 | 说明 |
| --- | --- |
| 实验名称 | 基于Web的漏洞与组件信息管理系统 |
| 实验形式 | 小型项目开发，AI 辅助 |
| 完成周期 | 4 周（建议周期，提交日期教师通知为准） |
| 总分 | 30 分 |
| 技术栈 | 主流 Web 技术自选 |
| 数据来源 | 教师提供的 CVE 漏洞信息及 Maven 组件信息 SQL |
| 运行要求 | 可在本地复现运行 |

## 二、实验目标

通过本实验，学生应：

1. 熟悉 Web 应用从数据设计、前后端开发、接口联调到运行测试的基本过程。
2. 了解前端、后端和数据库的工作机制及各自的作用范围。
3. 理解三者之间的职责边界，以及前后端通过 HTTP 协议进行数据通信的方式。
4. 在 AI 辅助下开展项目实践，将自己在产品设计和工程实现等方面的想法落地。

## 三、任务说明

### 3.1 系统组成

项目必须包括以下三个部分：

- **前端展现**：负责数据展示、表单输入、用户操作和结果反馈。
- **后端应用**：提供 HTTP 接口，处理业务逻辑并访问数据库。
- **数据库**：存储 CVE 漏洞信息和 Maven 组件信息，实现数据持久化。

前端不得直接访问数据库，必须通过 HTTP 请求与后端通信。后端应采用 REST 风格的资源导向接口设计，使用合适的 HTTP 方法与状态码，并通过响应体补充数据或错误详情。

### 3.2 技术选型

本实验不限制具体技术栈，学生可根据个人经验和项目需要自由选择：

- **前端**：可以使用 Vue、React、Angular 等框架，也可以直接使用 HTML、CSS 和 JavaScript 完成。
- **后端**：不限制编程语言和开发框架，只要能够提供 HTTP 接口并实现规定功能即可。
- **数据库**：不限制数据库类型和产品，只要能够保存教师提供的数据并支持项目所需的数据操作即可。

技术选型本身不作为评分依据。无论采用何种技术，项目都必须具备前端、后端和数据库三个部分，前后端通过 HTTP 协议通信，并能够按照 README 在本地运行。

### 3.3 功能要求

分别为 CVE 漏洞信息和 Maven 组件信息制作管理页面。

**CVE 漏洞信息模块**必须实现：

1. **查询**：展示数据列表，支持按 ID、名称等关键字段检索，并能查看记录详情。
2. **修改**：编辑已有记录并持久化更新。
3. **删除**：删除指定记录，操作前须进行确认。
4. **校验与反馈**：校验必填项和基本数据格式，展示成功、失败及无数据状态。

CVE 数据字段较多、结构复杂，并可能包含描述、影响范围、评分及关联信息等内容，不适合通过普通表单进行完整的手工录入。因此，本实验不要求 CVE 页面提供新增功能，CVE 初始数据通过教师提供的 SQL 导入。

**Maven 组件信息模块**必须实现：

1. **查询**：展示数据列表，支持按 ID、名称等关键字段检索，并能查看记录详情。
2. **新增**：通过表单创建记录并保存到数据库。
3. **修改**：编辑已有记录并持久化更新。
4. **删除**：删除指定记录，操作前须进行确认。
5. **校验与反馈**：校验必填项和基本数据格式，展示成功、失败及无数据状态。

查询功能仅要求针对各类数据的关键字段提供基本检索，例如 ID、名称等；不要求实现全字段检索、复杂组合筛选或高级搜索。

### 3.4 数据库要求

- 学生可根据所选技术栈重新设计数据库，但应保留原始数据的核心业务信息。
- 如果调整原始结构，应在报告中简要说明字段映射和修改理由。
- 提供可重复执行的建表、初始化、导入或迁移脚本。
- 项目重启后，已保存的数据仍应存在。

### 3.5 AI 辅助与记录要求

学生可以使用 AI 进行需求分析、代码生成、调试、测试和文档整理，但必须理解并验证最终结果。AI 使用记录应简要说明：

- 使用的工具和主要用途；
- 具有代表性的提示词或问题；
- 对 AI 建议的采纳、修改或否决；
- 对生成内容采用的验证方法。

以上 AI 使用情况应体现在实验报告中，但不要求提交完整聊天记录。

## 四、提交要求

1. 完整源代码及依赖声明。
2. 数据库建表、初始化或迁移脚本。
3. README，包括技术栈、配置方法、数据库初始化及前后端启动步骤。
4. 实验报告，记录项目开发过程中的主要思考、实践过程和问题总结，至少包括：
   - 对实验需求的理解，以及如何将总体要求细化为具体功能和实现任务；
   - 技术栈、数据结构、系统结构和关键功能的方案选择及决策依据；
   - 使用了哪些 AI 工具、AI 在需求分析、代码实现、调试或测试等环节中的具体作用，以及具有代表性的提示词或问题；
   - 对 AI 建议或生成内容所做的采纳、修改或否决，以及相应的判断依据；
   - 开发过程中遇到的主要问题、解决过程、验证方法和个人总结。
5. 5–8 分钟现场或录屏演示（形式以课程后续通知为准），覆盖项目启动、CVE 模块的查询、修改和删除、Maven 组件模块的 CRUD，以及一次前后端 HTTP 通信。

项目中不得提交真实密码、访问令牌或其他敏感信息。

## 五、考核标准

| 评分项 | 分值 | 主要考核内容 |
| --- | ---: | --- |
| 前端、后端与数据库结构 | 6 | 具备前端、后端和数据库三个部分；前后端通过 HTTP 通信；系统能够运行并完成数据持久化 |
| CVE 页面数据管理 | 6 | 能够正确完成 CVE 数据的查询、修改和删除；不要求新增功能 |
| Maven 组件页面 CRUD | 6 | 能够正确完成 Maven 组件数据的新增、查询、修改和删除 |
| 实验文档与 Pre 展示 | 6 | 实验文档内容完备，运行说明清楚；Pre 能够完整演示项目并说明主要实现 |
| 创意附加分 | 最高 6 | 在满足基础要求之外，能在产品设计、交互体验、功能拓展、技术或工程实现等方面具有合理创意 |
| **基础分** | **24** |  |
| **总分** | **30** | 基础分与创意附加分之和不超过 30 分 |

评分说明：只有页面效果而没有真实的后端处理和数据库持久化，不视为完成功能。CVE 模块不要求新增功能；Maven 组件模块须完成完整 CRUD。创意附加分根据完成质量酌情给出，总成绩不超过 30 分。

## 六、验收方式

教师将根据提交代码和材料进行审阅，将安排一个周中的课程对整体演示进行验收，并可能随机指定 CVE 记录进行查询、修改或删除，或指定 Maven 组件记录进行新增、查询、修改或删除。学生应能够说明：

- 前端、后端和数据库各自的作用；
- 一次 HTTP 请求从前端发出到数据库更新的完整过程；
- 数据模型和关键代码的基本设计；
- AI 参与的工作及其验证方式。
- 自己的创意点和思考

## 附录：创意附加分说明

创意附加分是基础要求之外的可选加分项。仅完成实验规定的页面、数据管理、校验、数据持久化和文档等内容，不作为创意加分项。

以下是创意方向的举例：

- **精美的 UI 设计**：以 UI 设计师视角，以界面风格统一，布局清晰，并具有良好的配色、图标、响应式适配和交互反馈。
- **具有表现力的展示**：以交互设计师视角，通过图表、仪表盘、风险等级标识、动画或其他可视化方式，使漏洞和组件数据更加直观。
- **进一步的产品思考**：以产品经理视角，在基础要求之外，实现登录、用户管理、角色权限、操作日志、批量操作、导入导出等功能。
- **完整的工程化实践**：以工程师视角，尝试引入更先进的技术点作为实验；或者编写单元测试或接口测试，让工程更健壮。
- **项目全过程管理**：以项目经理视角，对整个项目开发过程进行项目管理和追踪；使用 AI 模拟各个项目角色，通过文档管理和进度管理，展示对项目过程管理的理解。

以上创意点仅仅是方向上的提示和举例，学生有更多更自由的想法，并结合 AI 去实现。

但是，这次作业**不要**为你的 Web应用加入任何 Agent 能力，这是下节课的内容

创意数量不作为主要依据，更关注设计的合理性、实现完成度和实际效果。学生应在实验报告和演示中说明创意的设计动机、实现方式和验证结果。
