# 《现代 Web 开发》实践作业一实验报告

## 一、项目概况与需求理解

项目名称：SECUREBASE · 基于 Web 的漏洞与组件信息管理系统。

开发环境：Linux SSH 服务器、Docker Engine、Docker Compose；客户端通过 Windows PowerShell 的 SSH 端口转发，在本机浏览器使用系统。技术栈为 Vue 3 + TypeScript + Element Plus、Node.js + Express、mysql2、MySQL 8.4。

本报告记录本次实际实现的需求分析、方案选择、开发问题和验证过程。提交时请在封面补充姓名、学号、班级及课程要求的提交日期；以下内容不虚构个人信息。

对作业的理解是：需要完整的前端、后端和数据库三个部分，且管理操作必须真正改变持久化数据。前端不能直接访问数据库，也不能仅用本地数组或 localStorage 模拟 CRUD。CVE 只要求查询、详情、修改和删除；Maven 组件需要完整 CRUD。两类数据都需要基本检索、必填和格式校验、删除确认及成功/失败/无数据反馈。数据初始化必须可重复执行，重启后保持用户修改。

把总体需求细化为以下任务：

| 要求 | 具体实现 | 验证依据 |
| --- | --- | --- |
| 前后端通过 HTTP 通信 | Vue 发同源 /api 请求，Vite 代理到 Express | 通信测试、浏览器 Network、录屏请求实录 |
| 数据库持久化 | MySQL 数据卷；API 通过连接池读写 | 重建容器后查询修改、删除和日志 |
| CVE 查询、修改、删除 | 漏洞管理页及 GET/PATCH/DELETE API | 独立漏洞夹具的接口和浏览器测试 |
| Maven 完整 CRUD | 坐标生成 PURL、通用组件表单、列表和详情 | 新增、重复校验、编辑、确认/取消删除测试 |
| 原始数据保留 | 1000 条漏洞、398 条组件的全字段映射 | 原 SQL 与业务表逐字段比较 |
| 可重复初始化 | 数据库锁、迁移记录、事务导入标记 | 重复运行 db:init、容器重建 |
| 使用与开发文档 | README、API 文档、报告与演示说明 | 按文档命令操作，检查路径与脚本 |
| 合理创意 | 风险概览、操作日志、响应式界面、真实测试 | 聚合数量一致、日志快照、手机布局 |

实验不要求复杂搜索、CVE 新增或漏洞自动分析。本次没有加入 Agent 能力。

## 二、技术栈与系统结构决策

### 2.1 前端

选择 Vue 3 和 TypeScript，便于将列表、表单和详情抽成组件，同时保持字段和资源名称清楚。Element Plus 提供表格、分页、表单校验、弹窗与消息反馈，避免重复实现基础控件。Vite 负责开发服务和热更新。

界面采用统一工作台布局，左侧导航、顶部连接状态、右侧管理内容。风险等级使用颜色与中文文本同时表达，避免只依赖颜色。手机视口下导航变为横向，卡片重新排布，表格保持内部滚动。导航使用 SVG 图标并设置可访问名称，不依赖不同系统的特殊字符字体。

页面路由使用 hash，支持直接进入某个模块及从仪表盘携带检索条件跳转。当前规模只有四个页面，没有引入额外全局状态库或路由框架。

### 2.2 后端与数据库访问

选择 Express 和 TypeScript，使前后端共用语言。资源路径采用 /api/vulnerabilities 和 /api/components，分别用 GET、POST、PATCH、DELETE 表达查询、新增、部分修改和删除。CVE 不设置 POST 接口。

选择 mysql2 直接编写 SQL，而不是 ORM。原因是数据规模较小、教师已经提供 SQL，参数化查询和事务容易检查，也方便解释 HTTP 请求到数据库的完整过程。动态表名和字段名只来自代码白名单，用户输入作为占位符参数。分页大小和页码先校验为整数才用于 SQL。

错误统一为 JSON，400 表示校验错误，404 表示记录或接口不存在，409 表示唯一标识或版本冲突，201 表示新增成功，204 表示删除成功。健康检查实际执行 SELECT 1，不能仅返回静态“正常”。

### 2.3 容器与网络

用户要求前后端在同一个容器内、源码挂载、测试在 Docker 内完成，因此使用一个 app 开发容器同时运行 Vite 和 Express，数据库独立放在 db 容器。MySQL 单独运行便于管理数据卷，而前后端运行边界符合用户要求。

两个服务采用 host 网络，共享服务器网络命名空间，通过 127.0.0.1 通信。默认只监听服务器回环地址，Windows 浏览器通过 SSH -L 转发进入。前端使用相对路径 /api，Vite 代理请求，所以浏览器不会误把服务器 localhost 当作自己的数据库或后端地址。

镜像从 AWS ECR Public 拉取 Docker 官方 Node 与 MySQL 镜像，解决服务器无法直连 Docker Hub 的问题。浏览器运行库使用 Debian 官方源，Chromium 使用 Playwright 官方 CDN。源码不 COPY 到镜像，而是挂载到 /workspace；npm 缓存、浏览器、测试结果等临时内容放在仓库 tmp/，避免下载外溢。

## 三、数据结构与原始字段映射

### 3.1 原始数据观察

教师漏洞表 tmp_vul 无主键，包含来源、描述、影响范围、评分、CWE 等 15 个字段。标题可以为空。组件表 tmp_comp 以 PURL 为主键，包含 12 个字段，版本虽然 NOT NULL 但历史记录可以是空字符串。

SQL 的 INSERT 写死 osscore 数据库。漏洞描述存在换行、分号和反斜杠转义的单引号，因此不能用按行读取或直接按分号切割来导入。

组件文件并非纯 Maven 数据，实际生态有 github、generic、composer、npm、cargo、packagist 和未标注类型，没有 Maven 记录。本项目没有丢弃原始数据，而是在组件模块支持全部生态，并为新建 Maven 提供专用坐标录入。该文件与作业描述的命名差异应在课程验收时说明。

### 3.2 表设计

| 业务表 | 核心设计 |
| --- | --- |
| vulnerabilities | 保留 15 个原字段，新增自增 id、revision、created_at、updated_at；按 CVE 编号、风险等级和发布时间建立索引 |
| components | 保留 12 个原字段，新增自增 id、revision、created_at、updated_at；PURL 保留唯一约束，名称和生态有索引 |
| operation_logs | 资源类型、资源 ID、动作、标识摘要、before/after JSON、时间；不对业务记录设置外键，删除后日志仍保留 |
| schema_migrations | 初始化版本与应用时间，记录建表版本和 teacher-data-v1 导入标记 |

不把 CVE 编号当成必然唯一的数据库主键，因为原始表没有该约束；内部 ID 更适合稳定定位。PURL 包含斜杠等字符，保留为唯一业务标识，但用内部 ID 构造 API URL。

### 3.3 字段映射说明

| 原字段 | 业务表字段与调整 | 原因 |
| --- | --- | --- |
| source_id / source_name | vulnerabilities 同名字段 | 保留来源身份 |
| source_publish_date / source_update_date | 同名，TIMESTAMP 改 DATETIME | 保留原时间值，明确按 UTC 解释，减少会话时区转换 |
| source_link | 同名 | 保留来源链接，编辑时限制 HTTP(S) |
| affected_version | 同名 MEDIUMTEXT，API 解码为数组 | 保留原始 JSON 文本，不强行建立未知关系 |
| cvss_score_v4 / v3 / v2 | 同名 FLOAT | 原值完整保存；表单提供 0–10 校验 |
| severity / type | 同名可空文本 | 保留原风险与分类，缺失值在展示时标为未知 |
| cwe_id | 同名，由短文本扩为 TEXT | 避免后续多个 CWE 时受原长度限制，API 使用数组 |
| description / cve_id / title | 同名，保持可空存储结构 | 保留描述、编号和原始缺失标题；编辑描述需要非空 |
| purl | components 同名，保留唯一约束 | 组件业务唯一标识 |
| cpe / type / vendor / name / version | components 同名 | 原字段完整映射，历史空版本保留 |
| license / description / repository / language | components 同名 | 保留许可证、描述、仓库和语言 |
| publish_date / record_time | 同名，日期统一为 DATETIME | 来源时间与系统更新时间分离 |
| 无对应字段 | id / revision / created_at / updated_at | 用于定位、并发控制和本系统变更时间 |

原始 SQL 文件保持不变。没有根据 CPE 文本自动断言“这个组件受该漏洞影响”，因为真实版本匹配需要额外规则，本实验数据没有提供可靠外键。

## 四、关键功能实现

### 4.1 幂等导入

初始化先获取按数据库区分的锁，再执行 IF NOT EXISTS 建表。导入时将原表转换为连接级临时表，将 INSERT 的 osscore 前缀去掉，按引号和转义边界拆分 SQL。临时表中的字段逐一映射到目标表。

业务数据和 teacher-data-v1 标记在同一个事务中提交，失败则回滚。连接关闭清理临时表。已有导入标记时只检查建表，不重新导入。因此再次启动、执行 db:init 或重建容器，不会覆盖修改、复制重复记录或恢复已删除记录。

### 4.2 查询与详情

两类列表采用后端分页，不一次性把全部记录发到浏览器。关键字支持内部 ID 和业务关键字段；漏洞标题为空时仍可搜索描述。LIKE 使用显式转义，用户输入的百分号和下划线按字面匹配。详情接口返回完整字段，列表返回摘要，长描述不会撑开表格。

前端列表加载失败时展示错误与重试按钮，无数据时展示清楚的空结果，加载时显示遮罩。详情抽屉也处理等待和失败状态。删除某页最后一条数据后，会回退到有效页码。

### 4.3 新增与字段校验

Maven 新增由 groupId、artifactId、version 生成 PURL，并填写 name、vendor 和 type。也提供通用组件录入模式。新增名称、PURL、版本必填；历史组件编辑允许保留空版本，避免无法维护教师原始数据。

前端校验提升交互速度，后端负责最终校验。后端拒绝未知字段、非法日期、评分越界、非法链接和 CWE 格式错误。重复 PURL 由数据库唯一约束兜底，转换为 409 和字段级提示，表单不会被清空。

### 4.4 修改、删除和并发

详情返回 revision。修改时开启事务并锁定记录，确认请求版本与当前版本一致，才执行更新、增加 revision、写入日志并提交。旧版本返回 409，避免两个编辑窗口互相覆盖。

删除操作先在前端显示确认框，取消不会发 DELETE。页面发送记录版本，后端再检查记录是否已被其他操作修改。删除数据与写删除日志也在同一个事务中完成，成功返回 204。

日志保存变更前后数据库快照。新增前快照为 null，删除后快照为 null。没有登录系统，因此日志不声称记录了操作者身份。

### 4.5 一次 HTTP 请求的完整过程

以修改组件描述为例：

1. 浏览器通过 GET /api/components/:id 获取详情与 revision。
2. 用户输入描述并点击保存，前端提交 PATCH 和 JSON 请求体。
3. Vite 在服务器将 /api 请求代理到 Express。
4. Express 检查参数、字段白名单、必填和格式，通过 mysql2 从连接池取连接。
5. 后端开启事务，SELECT FOR UPDATE 读取记录并核对 revision。
6. 更新 MySQL、增加版本、写 operation_logs，然后 COMMIT。
7. 后端返回 200 和更新后的记录；前端提示成功并重新获取列表。
8. 若校验或数据库约束失败，返回合适错误；事务回滚，前端保留输入。

## 五、创意设计与工程实践

风险概览的动机是让数据规模和风险分布一眼可见，而不是只展示长表格。条形图和生态分布直接关联筛选，统计来自 MySQL 聚合查询；没有使用假数据。初始高危与严重总数为 507，其中 HIGH 448、CRITICAL 59，另外 MEDIUM 388、LOW 105。数量随着数据库真实操作变化。

操作日志的动机是解释“修改发生了什么”，在删除后也保留记录标识和原快照。它同时用于演示数据库事务的作用：业务更新与日志必须一起成功，不应该出现更新失败却生成成功日志。

工程实践包含 TypeScript 检查、真实 API 测试、SQL 导入全字段核对、独立夹具的持久化测试和 Playwright 浏览器测试。测试使用独立标记记录并清理，不把删除教师数据当作测试方案。页面支持响应式布局和可访问按钮名称。

这些功能在基础要求之外有明确目的，但创意附加分仍由教师按实际效果评定。

## 八、验证方法与结果

所有检查均在 app 容器内完成。使用的命令、最终结果和录屏信息见 [验收记录](验收记录.md)。

验证重点：

- `npm run check` 和 `npm run build`：前后端类型检查与完整编译。
- `npm run verify:import`：首次导入尚未修改教师记录时，1000 条漏洞、398 条组件的所有原始字段逐值一致。
- `npm test`：九项单元/集成/通信测试，覆盖 SQL 分割、日期和评分边界、CRUD、重复 PURL、并发冲突、日志事务、未知接口和真实 MySQL。
- `npm run test:e2e`：四项用例全部通过，真实 Chromium 操作页面，覆盖概览、空状态、错误重试、手机布局、Maven CRUD、CVE 修改删除以及日志快照。
- 持久化夹具：通过 API 创建和修改独立记录、删除另一记录，重建 app 与 db 后检查修改仍在、删除仍为 404、日志保留，再清理夹具。
- 演示：真实浏览器录制，使用专用夹具，展示教师记录查询、CVE 修改删除、Maven CRUD、启动日志与一次实际 HTTP 请求。

### 全新环境验证

另建独立 Compose 项目，使用独立数据卷与端口，验证首次启动自动导入并经前端代理返回 1000 条漏洞、398 条组件、0 条操作日志；原始字段核对一致。验收结束清理独立项目，主环境保持运行。

## 九、总结与答辩准备

本项目把前端、后端和数据库的职责连成了可运行的闭环。实现中最需要关注的并非表格样式，而是数据导入边界、错误反馈、唯一约束、事务和重启后的状态一致性。保留原始空值与不完整数据，比为了表单方便强行补值更符合数据管理的目的。

当前的合理限制是：这是本地课程工具，没有用户认证；日志不能识别操作者；UI 库仍可做按需加载；检索为基本字段搜索，不是全文搜索引擎；PURL 使用适合本作业的基本格式检查，没有实现全部包 URL 规范的解析；没有实现 CPE 版本匹配或漏洞扫描。

提交者应能现场解释：一条 HTTP 请求如何触发事务，revision 为什么防止覆盖，数据卷和导入标记各自解决什么问题，为什么没有 CVE 新增，以及原始组件数据为什么包含其他生态。可根据本人对代码的理解补充学习体会，但不应把 AI 自动化验证写成自己未实际进行过的人工操作。
